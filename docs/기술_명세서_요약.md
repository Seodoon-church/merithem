# Merithem 통합 플랫폼 기술 명세서 요약

## 1. 시스템 개요

### 시스템 아키텍처
3-Tier 마이크로서비스 아키텍처 기반, 각 서비스는 독립적으로 확장 가능

| 계층 | 구성 요소 |
|------|-----------|
| 프레젠테이션 | React 18.x + TypeScript, Next.js 14.x (SSR/SSG), PWA 지원 |
| 애플리케이션 | API Gateway (Spring Cloud Gateway), 회원/상품/주문 서비스 (Spring Boot 3.x), AI 진단 서비스 (Python FastAPI + TensorFlow), 구독 관리 서비스 (Spring Boot 3.x) |
| 데이터 | PostgreSQL 15.x (메인 DB), Redis 7.x (캐시/세션), MongoDB 6.x (이미지 메타데이터), AWS S3 (이미지 저장소) |

## 2. 기능 명세

### Phase 1: 사용자 및 디바이스 관리

#### 회원 관리
- 회원가입: 이메일 및 소셜 로그인(카카오/네이버/구글) 지원
- 로그인: JWT 기반 인증(Access 30분, Refresh 14일)
- 마이페이지: 회원정보 수정, 등록 디바이스 관리, 진단 이력 조회, 구독 관리

#### 디바이스 등록 및 관리
- 디바이스 등록: 시리얼 번호 입력 및 인증, 구매처 선택(병원/뷰티샵/약국/해외)
- 디바이스 관리: 등록 디바이스 목록 조회, 디바이스별 사용 이력
- 제품 정보: LUMI+ 제품 스펙, 사용 방법 동영상, FAQ

#### 알림 시스템
- 펌웨어 업데이트, 진단 추천 알림(월 1회), 구독 갱신 알림, 이벤트/프로모션

## 3. 데이터베이스 설계

PostgreSQL을 메인 데이터베이스로 사용하며, 총 12개 주요 테이블로 구성

### 주요 테이블 구조

#### users (회원)
```sql
user_id (PK), email (UNIQUE), password, name, phone, birth_date, gender,
skin_type, points, created_at, status
```

#### devices (등록 디바이스)
```sql
device_id (PK), user_id (FK), serial_number (UNIQUE), nickname, purchase_place,
purchase_date, registered_at, firmware_version, status
```

#### diagnoses (진단)
```sql
diagnosis_id (PK), user_id (FK), device_id (FK), image_url, skin_type, wrinkle_score,
pigment_score, pore_score, total_score, skin_age, created_at
```

#### subscriptions (구독)
```sql
subscription_id (PK), user_id (FK), plan_type, status, start_date, next_billing_date,
billing_amount, created_at
```

#### subscription_deliveries (구독 배송)
```sql
delivery_id (PK), subscription_id (FK), delivery_date, tracking_number, status,
products_json, address, created_at
```

### 인덱스 전략

| 테이블 | 인덱스 | 목적 |
|--------|--------|------|
| users | idx_users_email | 이메일 기반 로그인 |
| devices | idx_devices_serial | 시리얼 번호 인증 |
| | idx_devices_user_id | 회원별 디바이스 조회 |
| diagnoses | idx_diagnoses_user_created | 회원별 진단 이력 |
| subscriptions | idx_subscriptions_user_status | 활성 구독 조회 |

## 4. API 명세

### API 설계 원칙
- RESTful API 표준 준수
- HTTP 상태 코드 표준 사용
- JSON 형식의 요청/응답
- JWT 기반 인증
- API 버전 관리 (/api/v1)
- Rate Limiting (분당 100회)

### 주요 엔드포인트

| Method | Endpoint | 설명 |
|--------|----------|------|
| **인증 API** |
| POST | /api/v1/auth/signup | 회원가입 |
| POST | /api/v1/auth/login | 로그인 (JWT 발급) |
| POST | /api/v1/auth/refresh | 토큰 갱신 |
| **디바이스 API** |
| POST | /api/v1/devices | 디바이스 등록 (시리얼 번호 인증) |
| GET | /api/v1/devices | 내 디바이스 목록 조회 |
| GET | /api/v1/devices/{id} | 디바이스 상세 조회 |
| DELETE | /api/v1/devices/{id} | 디바이스 등록 해제 |
| **진단 API** |
| POST | /api/v1/diagnoses | 피부 진단 요청 |
| GET | /api/v1/diagnoses/{id} | 진단 결과 조회 |
| GET | /api/v1/diagnoses/history | 진단 이력 조회 |
| **구독 API** |
| POST | /api/v1/subscriptions | 구독 신청 (결제 포함) |
| GET | /api/v1/subscriptions/me | 내 구독 정보 조회 |
| PUT | /api/v1/subscriptions/{id} | 구독 플랜 변경 |
| GET | /api/v1/subscriptions/{id}/deliveries | 구독 배송 내역 |

## 7. 개발 환경 및 배포

### 개발 환경

| 환경 | 구성 |
|------|------|
| Development | 로컬 개발 환경, Docker Compose, Mock 데이터 |

### CI/CD 파이프라인
- **코드 저장소**: GitHub (Private Repository), 브랜치 전략: Git Flow
- **CI**: GitHub Actions - 코드 푸시 시 자동 빌드, 단위 테스트, 정적 분석, Docker 이미지 빌드 및 ECR 푸시
- **CD**: ArgoCD - GitOps 방식 배포, Helm Chart 사용, 자동 롤백 설정
- **모니터링**: Prometheus + Grafana (메트릭), ELK Stack (로그), Sentry (에러 추적)
